# Ubiquitous Language

Canonical vocabulary for the project.
When other docs use different wording, this file wins.

## Term Rules

- One canonical term per concept.
- Prefer domain terms over storage terms.
- Prefer short, stable wording that LLMs can reuse consistently.
- If a feature introduces a new domain term, update this file first.

## Canonical Terms

| Term                     | Meaning                                                                                                                                                                                                                                                                                                                                                                                 | Allowed aliases                  | Avoid                                  |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- | -------------------------------------- |
| `Note`                   | The primary logical document.                                                                                                                                                                                                                                                                                                                                                           | document                         | file, page                             |
| `Note catalog row`       | The lightweight list representation of a Note used by the Workspace Catalog. It keeps the same top-level fields as a Note, but omits the `content` field because the app keeps full note bodies in shared client state.                                                                                                                                                                 | note preview, list item payload  | partial note, cached note              |
| `Note title`             | Human-readable title shown in the UI. It is a Derived Property computed from the note `id` basename (without `.md`). It is edited in the template area and persisted by renaming the note `id`. A user-defined `title` frontmatter key is shadowed by the derived value.                                                                                                                | note name, display name          | file name                              |
| `Note description`       | A 120-character stripped-markdown preview of note Content. It is a Derived Property computed at load and on save. Used by the notes list.                                                                                                                                                                                                                                               | note preview text                | note summary                           |
| `Derived Properties`     | Application-computed per-note fields (`title`, `description`) that exist only in memory, never serialized to frontmatter. They shadow any user-defined Properties with the same key names. Recomputed at note load and on save/rename.                                                                                                                                                  | computed properties              | cached properties, virtual properties  |
| `Content`                | The rich content section of a note.                                                                                                                                                                                                                                                                                                                                                     | —                                | body, markdown body                    |
| `Properties`             | User-defined note data stored as top-level fields on a Note. Values may be scalars, arrays, or nested objects. Serialized as top-level YAML frontmatter keys. Managed through the app’s note editing workflows and persisted with the note document.                                                                                                                                    | user properties, property values | storage fields, metadata               |
| `Application Properties` | Application-managed per-note state (e.g. `favorite`). Controlled through dedicated UI, not user-editable in the property editor. In memory these are flat top-level Note fields. On disk they are serialized under the `app` namespace key in YAML frontmatter (see D009).                                                                                                              | app properties                   | reserved properties, system properties |
| `System Properties`      | Read-only storage-provided values (e.g. `createdAt`).                                                                                                                                                                                                                                                                                                                                   | system fields                    | note properties, derived fields        |
| `Settings`               | The application dialog for viewing and updating persisted `AppConfig` values such as locale, feature flags, editor behavior, panel visibility, and theme choices.                                                                                                                                                                                                                       | preferences                      | config editor, settings file           |
| `Onboarding guide`       | The blocking first-run setup carousel shown above the workspace shell until the user finishes the required initial configuration. Its progress and completion state are persisted in app-scoped storage outside the Vault.                                                                                                                                                              | first-run guide, setup carousel  | tutorial modal, welcome wizard         |
| `Non-distraction mode`   | Session-only layout state toggled from `NoteControls` that hides SidebarPanel and NotesListPanel until turned off; restores the prior visibility of those panels. While active, the note editor column uses half of the center panel width and is horizontally centered. Not persisted in app config.                                                                                   | focus writing mode               | zen mode, fullscreen mode (avoid)      |
| `Template`               | Rendered wrapper around content; not edited inline.                                                                                                                                                                                                                                                                                                                                     | template wrapper                 | page wrapper                           |
| `Storage`                | Persistence implementation for logical notes. Configured via `storageType`: `filesystem` (default) stores notes as Markdown files in the Vault. The storage boundary remains designed so additional backends can be added later without changing higher-level app logic.                                                                                                                | storage adapter, adapter         | —                                      |
| `Platform API`           | The raw I/O boundary between client-side adapters and the host environment. In the desktop app it is implemented with Tauri IPC plus desktop-safe asset URLs.                                                                                                                                                                                                                           | platform adapter                 | backend client, fetch helper           |
| `Vault`                  | The configured top-level directory for filesystem storage. Only relevant when `storageType` is `filesystem`.                                                                                                                                                                                                                                                                            | notes location, storage root     | workspace root                         |
| `Tag`                    | A string label derived from inline hashtags in note Content. Stored as the top-level `tags` Property without the `#` prefix, and used by the sidebar tag filter.                                                                                                                                                                                                                        | hashtag                          | label chip, category                   |
| `Tag filter state`       | The tri-state of a Tag in the sidebar filter: idle (default), active (transient selection), or pinned (sticky selection). At most one tag can be active; multiple can be pinned.                                                                                                                                                                                                        | tag state                        | tag mode, tag status                   |
| `trashedAt`              | An ISO 8601 string Application Property set when the user soft-deletes a note. Its presence means the note is in the Trashed logical state, excluded from normal workspace lists, and serialized under the `app` namespace key in YAML frontmatter. Cleared when the note is moved to Inbox or a folder (restore).                                                                      | trash timestamp                  | soft-deleted at, deletedAt             |
| `favorite`               | A boolean Application Property set when the user marks a note as a favorite. When true, the note appears in the Favorites sidebar view (non-trashed notes only) and is serialized under the `app` namespace key in YAML frontmatter. Omitted when not favorited.                                                                                                                        | starred                          | bookmark                               |
| `pinned` (note)          | A boolean Application Property set from `NoteControls` when the user pins a note. When true, the note sorts to the top of the notes list for whichever sidebar view it belongs to and is shown with an accent-tinted row background; serialized under the `app` namespace key in YAML frontmatter. Omitted when not pinned. Not the same concept as a pinned Tag in the sidebar filter. | note pinned                      | tag pinned (avoid for this)            |
| `webhook`                | An optional string Application Property: an HTTPS URL of a third-party endpoint. Set from `NoteControls`; when present, the app may POST a JSON payload (including `event` and a full note snapshot) after a successful note save or after the note is moved to trash. Serialized under the `app` namespace key in YAML frontmatter. Omitted when unset.                                | outbound webhook URL             | callback URL                           |
| `wide`                   | A boolean Application Property set from `NoteControls`. When true, the note template uses reduced inline padding (`2rem`) for a wider content area. Serialized under the `app` namespace key in YAML frontmatter. Omitted when not wide.                                                                                                                                                | stretched                        | expanded, fullwidth                    |
| `Favorites`              | The sidebar workspace view that lists notes with `favorite` true, excluding trashed notes.                                                                                                                                                                                                                                                                                              | favorites list                   | starred notes view                     |
| `Trashed`                | The sidebar workspace view that lists only notes with a `trashedAt` Application Property.                                                                                                                                                                                                                                                                                               | trash, bin                       | deleted items view                     |
| `Folder path`            | A vault-relative path identifying a folder in the sidebar (e.g. `Work`, `Work/Archive`). Used as the key for folder views, folder metadata, and drag-drop targets.                                                                                                                                                                                                                      | folder name (for top-level only) | folder id, folder key                  |
| `Folder metadata`        | Per-folder workspace customization (currently an optional emoji icon for the sidebar), keyed by folder path. Stored in `meta.yaml` as YAML, separate from `AppConfig` and from note files.                                                                                                                                                                                              | folder icon settings             | folder config file in each directory   |
